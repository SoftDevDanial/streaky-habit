### Observations (not filed)

1. **A slow second click deletes, as T7 records.** An event gap of 519 to 721 ms at 1440x900 with the mouse, and 520 to 708 ms at 412x915 with touch, deletes through the overlap. The spec's T7 residual ("a second, deliberate click 500 ms or more after opening deletes") covers it. Worth knowing: Windows lets a user set the double-click interval up to 900 ms, so a person with a slow setting whose double click lands in an overlap (1000 px and wider with a row level with the dialog, or phones up to about 450 px) still deletes. The window length is ORCH's ruling; a control that does not depend on time would be to ignore a "Delete habit" click whose pointer position lies inside the trash button that opened the dialog.
2. **"Delete habit" is a silent no-op for 500 ms, for the keyboard too (R13 note 1).** A quick Enter, Tab, Enter inside 500 ms leaves the dialog open with no feedback and the next Enter deletes. Documented, measured, not a defect.
3. **The page guard holds keyboard-made clicks as well as mouse ones.** `swallowTapThrough` does not look at `detail`: Enter on the focused trash button 118 ms after a mouse Cancel was stopped, and an Enter that submits the add form inside 500 ms of a mouse Cancel made no add (the list stayed at 3 habits). Only a person who mixes mouse and keyboard within half a second can see it. Within "the page ignores clicks for 500 ms", not beyond it.
4. **Floor browsers are unverified** (only Chromium is run). The guards rely on `event.timeStamp` being the browser's event time and on `event.detail` being 0 for a keyboard click and above 0 for a touch tap. Both hold in Chromium; a browser that reports a touch tap with `detail` 0 would leave the page guard off for that gesture.
5. **The dialog's accessible name carries the two invisible marks** (`aria-labelledby` points at `#del-title`; the aria snapshot is `alertdialog "Delete "<U+2068>Plain name<U+2069>"?"`). Screen readers normally skip them; not measured with one.
6. **Tooling note for whoever extends the tests:** the writing tool turns backslash-u escape text in a file it writes into the raw character (the conftest comment on `FSI` and `PDI` says the same). Build such characters from code points (`chr()`), as `conftest.py` and this folder's `chars.py` do.
