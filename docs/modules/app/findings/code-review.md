## BLOCKER

### CR-01. The `@R36` room test reads the host's padding before the app's close handler has run (bug, test). The app is right
- **Symbol.** `tests/browser/test_day_editor.py` `test_R36_on_a_phone_the_host_of_p1_gets_room_while_p1_is_open_over_it_and_loses_it_when_p1_closes`. App side `onPopupClose` in `src/app.js`, which calls `popups.clearDayRoom`.
- **Failure.** Close (or the backdrop) calls `dialog.close()`. `open` turns false at once, and the `close` event, where `onPopupClose` releases the room, is a queued task. In Chromium the click on the P3 day had focused it, and the browser's own focus restore inside `close()` focuses it again at once. So `expect(host_day(...)).to_be_focused()` passes before `onPopupClose` has run, and the single `page.evaluate(SIGHT_JS, ...)` that follows reads the room. Measured on the failing row `360x780 P3 2026-07-20`, 8 tries per way. As written, 5 of 8 read `["293px", "293px"]`. With the suite's own `watch_close` before the click and `wait_for_close` before the read, 8 of 8 read `["24px", ""]`. In WebKit both ways read `["24px", ""]` 16 of 16, because WebKit's own restore goes to P3's `dialog`, so the focus expectation waits for the app. The synchronised read is still red 8 of 8 when the room is never released (mutant A2), so the fix keeps the control. Task 22 judgment call 5 named this race for "earlier focus-after-close checks" and left it.
- **Ruling on the code side.** No defect. R36 puts the release in the branch of `onPopupClose` that clears the `is-open` marks, before focus returns, and the code does exactly that. The stale room lives one frame. Releasing it in the click path as well would add a second teardown path for Close and the backdrop only (Esc reaches the app only through the `close` event), so one rule would live in two places. Not recommended.
- **Fix.** In this test take `watch = watch_close(page, "dialog.dlg-day")` before `CLOSE_P1[action](page)` and before `page.mouse.click(5, 5)`, and replace the `wait_for_function("() => !document.querySelector('dialog.dlg-day').open")` with `wait_for_close(watch)`, then read. Use the same wait in the five tests that read focus after a close with only the `open` wait (`test_R36_R40_p1_closes_...`, `test_R36_R39_a_p4_day_opens_p1_over_p4_on_a_desktop`, `test_R38_R40_p3_closes_...`, `test_R39_R40_p4_closes_...`, `test_R33_R40_p2_closes_...`). Amend R36's sentence "before focus returns to the day button" to "before the app returns focus to the day button", because in Chromium the browser returns it first, inside `close()`.

### WR-12. Four new comments say the focus read after the close event is the app's, and in Chromium it is not (doc rot, control claim)
- **Symbols.** The comment after `wait_for_close(watch)` in `test_R36_R40_p1_closes_and_gives_focus_back_to_its_day` (`test_day_editor.py`, "so the reads below are the app's"), in `test_R38_R40_p3_closes_and_gives_focus_back_to_overview` and `test_R39_R40_p4_closes_and_gives_focus_back_to_the_year_that_opened_it` (`test_overview.py`) and in `test_R33_R40_p2_closes_and_gives_focus_back_to_its_year` (`test_year.py`), each "so the focus read is the app's". All four came in `7d3bd78`, copied from the older comment in `test_R40_R14_a_backdrop_click_closes_that_popup_only` (`test_popups.py`, "so the focus read below is the app's").
- **Failure.** Mutant A1 (the app returns no focus to a connected opener) passes every row of these five tests and of the two other CR-01 tests in Chromium, 30 of 30, and fails all 30 in WebKit. The wait proves that the app's close handler has run. It does not prove that the focus read came from it, because in Chromium the browser's own restore inside `close()` lands on the same opener. WR-06 took that claim out of `SETTLE_MS`, and the round wrote it into four tests in the same pass. The tests themselves are right, and R40's focus is gated by their WebKit run, which R30 makes blocking. The comments say the Chromium read shows the app's focus, so a reader who trusts them may treat the WebKit run as optional.
- **Fix.** Say it once, in the docstring of `watch_close` in `tests/browser/conftest.py`, for example "Waiting for the close event proves the app's close handler has run, so what it clears can be read. It does not show who moved focus. In Chromium the browser's restore lands on the same opener, so R40's return of focus is proven by the WebKit run." Then shorten the five comments to `# the app's close handler has run (conftest watch_close)`.
